## 1. Purpose & Scope

Phase 1 established a configurable policy engine, and Phase 2A introduced Evidence Confidence, Model Consensus, and Freshness.

**Phase 2B** enriches the query-time intelligence layer with:
1. **Score Stability / Volatility**: Quantifying temporal score variance and trajectory across sequential validation runs.
2. **Score Range Spread & Direction Flips**: Measuring absolute score dispersion ($\Delta S$) and trajectory reversals ($D_{\text{flips}}$).
3. **Level-1 Cross-Context Generalization**: Measuring feature consistency across sampling intervals within matching market/window/project contexts.
4. **Explicit Multi-Dimensional Risk Badges**: Providing granular, transparent risk tags (`[DEGRADED]`, `[SPLIT]`, `[STALE]`, `[UNSTABLE]`) without an opaque composite scalar score.

## 2. Mathematical Specifications `[IMPLEMENTED & VERIFIED]`

### 2.1. Score Volatility & Trajectory Variance ($N \ge 3$)
Implemented in [`apps/chain_replay_ml/production_validation/recommendation_policy.py`](file:///c:/Users/admin/PycharmProjects/AruMLStudio/apps/chain_replay_ml/production_validation/recommendation_policy.py#L695-L775) via `compute_score_volatility()`:

For features with $N \ge 3$ validation runs, the engine reconstructs the sequential cumulative evidence score trajectory $S_1, S_2, \dots, S_N$ chronologically:

$$\sigma_S = \sqrt{\frac{1}{N - 1} \sum_{t=1}^N (S_t - \bar{S})^2}$$
$$\text{Score Range Spread } \Delta S = \max(S_1, \dots, S_N) - \min(S_1, \dots, S_N)$$
$$\text{Direction Flips } D_{\text{flips}} = \sum_{t=2}^{N-1} \mathbb{I}\Big(\operatorname{sgn}(S_t - S_{t-1}) \neq \operatorname{sgn}(S_{t+1} - S_t)\Big)$$

- **$N < 3$ Runs**: Returns `volatility_score = None`, `score_range = None`, `display_text = "⚪ N/A (< 3 runs)"`.
- **$\sigma_S < 15.0$**: `🟢 Stable (σ=X.X)`
- **$15.0 \le \sigma_S < 35.0$**: `🟡 Moderate (σ=X.X)`
- **$\sigma_S \ge 35.0$**: `🔴 Volatile (σ=X.X)`

### 2.2. Level-1 Cross-Context Generalization ($K \ge 2$)
Implemented via `compute_context_generalization()`:

Level-1 comparability is defined as contexts sharing identical `market`, `sliding_window`, and `feature_project_id`, differing only by `sampling_interval_sec` (e.g. NIFTY 3s vs NIFTY 6s):

$$G = A_{\text{context}} \times \left(1.0 - \min\left(1.0, \frac{\Delta S_{\text{context}}}{100.0}\right)\right)$$

Where:
- $A_{\text{context}}$ is the agreement ratio of dominant recommendations across comparable intervals.
- $\Delta S_{\text{context}} = \max_{c} S(f, c) - \min_{c} S(f, c)$ is the cross-interval score range.

#### Classification Bands:
- **$K < 2$ Contexts**: Displays `⚪ Single Context`.
- **$G \ge 0.75$**: `🟢 Universal (G=0.XX)`
- **$0.50 \le G < 0.75$**: `🟢 Scale-Robust (G=0.XX)`
- **$0.25 \le G < 0.50$**: `🟡 Scale-Sensitive (G=0.XX)`
- **$G < 0.25$**: `🔴 Scale-Specific (G=0.XX)`

---

### 2.3. Explicit Multi-Dimensional Risk Badges
Implemented via `derive_risk_badges()`:

Instead of creating a lossy scalar risk score, the system exposes explicit condition tags:
- **`[DEGRADED]`**: `evidence_score <= -40.0`
- **`[SPLIT]`**: `is_consensus_tie == True`
- **`[STALE]`**: `freshness_label == "Stale"` ($> 30\text{d}$)
- **`[UNSTABLE]`**: `stability_label == "Volatile"` ($\sigma_S \ge 35.0$)
