## 1. Architectural Purpose & Boundaries

**Phase 3D establishes Feature Promotion, Graduation & Registry Governance.**

While Phases 3A, 3B, and 3C establish the closed-loop recommendation $\to$ candidate selection $\to$ model training $\to$ validation $\to$ evidence feedback loop, **Phase 3D governs what happens when an experimental feature earns permanent status**.

### 1.1. Core Architectural Principle: No Duplicate Scoring Engine
Phase 3A already deterministically qualifies experimental features as `PROMOTION_CANDIDATE_QUALIFIED` and awards the `[PROMOTION]` badge based on authoritative thresholds (consecutive `KEEP` votes $\ge 3$, unique models $\ge 3$, score $\ge +75.0$, confidence $\ge 0.70$).

**Phase 3D does NOT create a competing scoring system.** Instead, Phase 3D:
1. Collects the complete, multi-model Evidence Dossier.
2. Independently audits prerequisite integrity against policy.
3. Enforces the **Human Governance Review Boundary**.
4. Executes the **Registry Graduation Transaction** (assigning permanent `FRxxxx` identity).
5. Separately manages **Base Pipeline Promotion**.
6. Governs **Deprecation and Retirement** for degraded production features.

## 2. Taxonomy & Data Ownership Model

To eliminate architectural ambiguity, the table below establishes the strict boundaries between evidence, lifecycle state, and registry ownership:

| Concept | Nature | Storage Location | Mutability | Role |
|---|---|---|---|---|
| **Evidence History** | Historical Facts | SQLite table `recommendation_evidence` | **100% Append-Only & Immutable** | Raw facts of every model validation run (ranks, drops, recommendations). |
| **Lifecycle State** | Derived Summary | SQLite table `experimental_lineage_summary` | **Mutable Projection** | Current aggregated standing (`ACTIVE`, `PROMOTION_CANDIDATE`, `GRADUATED`). |
| **Registry Identity** | Production Asset | `data/feature_registry_store.json` | **Versioned JSON Store** | Authoritative catalog of permanent Feature IDs (`FRxxxx`), formulas, domains, and schemas. |
| **Promotion Candidate Status** | Ephemeral Advisory | Derived by Phase 3A Decision Engine | **Dynamic Query-Time Computation** | Qualification signal indicating a feature is ready for Human Governance Review. |
| **Graduation Status** | Permanent Milestone | `feature_registry_store.json` + Audit Log | **Permanent Transactional State** | Experimental feature accepted into Feature Registry with assigned `FRxxxx`. |
| **Base Pipeline Membership** | Production Pipeline Asset | `data/pipeline_registry_store.json` | **Versioned JSON Store** | Standard default features generated for all production models. |

## 3. Separation of Governance Stages

Graduation is not an all-or-nothing automatic leap into production pipelines. Phase 3D enforces **three strictly separated, human-governed milestones**:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                 THE GRADUATION PIPELINE                                │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│   [ EXPERIMENTAL FEATURE ] (Candidate undergoing validation cycles in Phase 3A/3B/3C)  │
│              │                                                                         │
│              ▼ (Phase 3A Decision Engine: 3 KEEPs, 3 models, Score ≥ 75, Conf ≥ 0.70)  │
│   [ PROMOTION CANDIDATE ] (Advisory state: Tagged [PROMOTION], top selection rank)     │
│              │                                                                         │
│              ▼ [HUMAN GOVERNANCE REVIEW 1 — Registry Reviewer Approval]                │
│   [ REGISTRY GRADUATION ] (Assigned permanent FRxxxx in feature_registry_store.json)  │
│              │                                                                         │
│              ▼ [HUMAN GOVERNANCE REVIEW 2 — Pipeline Lead Approval]                    │
│   [ BASE PIPELINE PROMOTION ] (Merged into standard dataset build pipeline)            │
│                                                                                        │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **Separation Invariant**: Graduating a feature into the Feature Registry (`REGISTRY_GRADUATION`) does **NOT** automatically add it to the Base Pipeline. Registry graduation makes the feature an officially cataloged asset; Base Pipeline promotion is an independent, higher-tier governance decision.

## 4. Universal vs. Context-Scoped Graduation

A critical capability of Phase 3D is preventing **Context Drift** during graduation. Not all great features are universal.

```
                                  ┌───────────────────────────┐
                                  │   PROMOTION_CANDIDATE     │
                                  └─────────────┬─────────────┘
                                                │
                       ┌────────────────────────┴────────────────────────┐
                       ▼                                                 ▼
             [ Cross-Context Tested ]                          [ Single-Context Only ]
               (Tested in K ≥ 2 contexts)                       (Tested in K = 1 context)
                       │                                                 │
          ┌────────────┴────────────┐                                    │
          ▼                         ▼                                    ▼
   [ G ≥ 0.50: Strong ]      [ G < 0.50: Scale-Specific ]                │
          │                         │                                    │
          ▼                         ▼                                    ▼
┌────────────────────────┐┌────────────────────────┐          ┌────────────────────────┐
│  UNIVERSAL GRADUATION  ││ CONTEXT-SCOPED GRADUATION │          │ CONTEXT-SCOPED GRADUATION │
├────────────────────────┤├────────────────────────┤          ├────────────────────────┤
│ • Valid across markets ││ • Locked to tested ctx │          │ • Locked to tested ctx │
│ • Eligible for Base PL ││ • BLOCKED from Base PL │          │ • BLOCKED from Base PL │
└────────────────────────┘└────────────────────────┘          └────────────────────────┘
```

### 4.1. Universal Registry Feature ($K \ge 2, G \ge 0.50$)
- **Requirement**: Evaluated across at least 2 distinct sampling intervals or markets ($K \ge 2$) with Generalization Index $G \ge 0.50$.
- **Privileges**: Can be included in any dataset build; eligible for future Base Pipeline Promotion review.

### 4.2. Context-Scoped Registry Feature ($K = 1$ or $G < 0.50$)
- **Requirement**: Evaluated in only 1 context, or demonstrated scale-specific / market-specific behavior.
- **Constraints**: Formally stamped with `allowed_contexts: ["NIFTY:3:standard:all"]`. Downstream dataset builders strictly block inclusion in incompatible markets. **Permanently barred from Universal Base Pipeline Promotion** unless subsequent multi-context validation proves generalization.

## 5. End-to-End Governance Workflows

### 5.1. Workflow 1: Feature Registry Graduation
1. **Dossier Compilation**: Reviewer opens `FeaturePromotionGovernanceDialog`. System compiles cumulative performance:
   - Total runs, unique models, consecutive keep streak.
   - Evidence score, confidence, volatility $\sigma_S$, generalization $G$.
   - Sample model validation snapshots and feature importance trajectories.
2. **Metadata Formulation**: Reviewer inspects and finalizes:
   - Domain classification (e.g. `order_flow`, `volatility`, `statistical`).
   - Feature Group assignment (e.g. `microstructure`, `options_greek`).
   - Formula and parameter schema freeze.
   - Context Scope (Universal vs Context-Scoped).
3. **Atomic Execution**:
   - `feature_registry_store.json` acquires new sequential ID (e.g. `FR0142`).
   - `experimental_lineage_summary` updates `lifecycle_status = 'GRADUATED'` with `graduated_feature_id = 'FR0142'`.
   - `data/feature_graduation_audit_log.json` logs the immutable approval record.

### 5.2. Workflow 2: Base Pipeline Promotion
1. **Prerequisites Audit**: Feature must already be a graduated Registry Feature with `FRxxxx` identity, Universal scope ($K \ge 2$), and $\ge 5$ production model runs.
2. **Pipeline Lead Review**: Lead engineer reviews computational overhead, latency budget, and schema dependencies.
3. **Pipeline Merge**: Feature name is added to `pipeline_registry_store.json`.
4. **Immunity Activation**: Feature immediately benefits from **Base Pipeline Immunity Rules E1–E4** (immune from hard exclusion in Auto Candidate Generation).

### 5.3. Workflow 3: Governed Deprecation & Retirement
1. **Deprecation Trigger**: When a Registry or Base Pipeline feature accumulates persistent negative evidence (e.g. consecutive `REMOVE` $\ge 3$, score $\le -40.0$, zero importance across all recent models), Phase 3A flags it as `DEPRECATION_CANDIDATE`.
2. **Deprecation Review**: Analyst reviews deprecation dossier in `FeaturePromotionGovernanceDialog`.
3. **Safe Retirement**:
   - `feature_registry_store.json` marks status as `deprecated`.
   - **Candidate Generation Parent Exclusion**: Deprecated features receive `is_candidate_generation_allowed = False` via `evaluate_candidate_training_eligibility()` and are immediately excluded from serving as interaction parents in `select_interaction_parent_features()`.
   - Downstream Model Builder alerts users if a legacy preset includes a deprecated feature.
   - **Historical models remain 100% functional** (feature code is not deleted from disk; historical packages continue inference without breaking).

## 7. Safety, Invariants & Backward Compatibility

- **Historical Evidence Immutability**: SQLite `recommendation_evidence` historical rows remain untouched.
- **Zero Schema Migrations**: No ALTER TABLE or SQLite schema modifications.
- **Strict Human Review**: Zero automatic/autonomous promotions.
- **Backward Compatibility**: Legacy models and presets without graduation metadata remain 100% compatible.
- **Phases 1–3C Invariance**: Scoring formulas, intelligence metrics, 4-boolean contract, and training provenance stamping remain 100% untouched.
