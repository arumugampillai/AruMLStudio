## 1. Purpose & Architectural Overview

This document defines how **AruMLStudio** evaluates accumulated Production Validation evidence into feature health, evidence scoring, priority ranking, candidate blocking, and Experimental promotion decisions.

```
    Production Validation (Out-of-Sample Holdout vs Unseen)
            │
            ▼
    KEEP / WATCH / REMOVE (Multi-Signal Diagnostic Rules)
            │
            ▼
    recommendation_evidence (Authoritative Immutable SQLite Event Log)
            │
       ┌────┴────┐
       ▼         ▼
feature_context_summary   experimental_lineage_summary
  (Context Projection)         (Lineage Projection)
       │                            │
       └──────────────┬─────────────┘
                      │
                      ▼
       QUERY-TIME INTELLIGENCE ENRICHMENT

       ┌──────────────┼──────────────┐
       ▼              ▼              ▼

```

- **Feature Analysis Lab answers**: *"Which features are non-redundant and statistically relevant for training?"*
- **Production Validation answers**: *"How did those features perform on true unseen forward data?"*
- **Scoring & Lifecycle Policy answers**: *"What does accumulated historical validation evidence indicate about the operational quality and future lifecycle of this feature?"*

## 2. Core Architectural Invariants

### 2.1. Evidence is Strictly Immutable
`recommendation_evidence` is the append-only ground truth event log. Validation events are permanent facts and are never updated, deleted, or overwritten by policy changes or projection rebuilds.

### 2.2. Dataset Context is the Authoritative Primary Boundary
All calculations, streaks, scores, and candidate blocking are strictly partitioned by **Dataset Context**:
$$\text{context\_id} = \mathtt{"ctx\_"} + \text{SHA256}(\text{market} + \text{interval} + \text{window} + \text{project})[:12]$$
- Evidence in `NIFTY 3s` never pollutes or blocks candidate features in `NIFTY 6s` or `SENSEX 1s`.

### 2.3. Feature Population Governs Lifecycle Behavior
- **Feature Registry**: Canonical features Materialized from Master Dataset. Immune from automated deletion and candidate blocking.
- **Base Pipeline**: Approved baseline features. Monitored for degradation; immune from automated deletion and candidate blocking.
- **Selected Experimental**: Experimental candidate features. Context-level candidate blocking gate prevents degraded candidates from regenerating; consistent clean performance qualifies `PROMOTION_CANDIDATE` for human governance.

## 3. Authoritative Evidence Scoring Formula (Phase 1)

Implemented in [`apps/chain_replay_ml/production_validation/recommendation_policy.py`](file:///c:/Users/admin/PycharmProjects/AruMLStudio/apps/chain_replay_ml/production_validation/recommendation_policy.py):

$$\text{raw\_score} = (w_{\text{keep}} \cdot M_{\text{keep}}) + (w_{\text{remove}} \cdot M_{\text{remove}}) + (w_{\text{watch}} \cdot M_{\text{watch}}) + (B_{\text{keep}} \cdot S_{\text{keep}}) + (P_{\text{remove}} \cdot S_{\text{remove}})$$

$$\text{evidence\_score} = \text{round}\Big(\max(S_{\min}, \min(S_{\max}, \text{raw\_score})), 2\Big)$$

### Default Configured Weights:
- $w_{\text{keep}} = +25.0$ (per model recommending KEEP)
- $w_{\text{remove}} = -35.0$ (per model recommending REMOVE)
- $w_{\text{watch}} = -10.0$ (per model recommending WATCH)
- $B_{\text{keep}} = +15.0$ (Streak Bonus per consecutive KEEP run)
- $P_{\text{remove}} = -25.0$ (Streak Penalty per consecutive REMOVE run)
- Clamping Invariant: $[S_{\min}, S_{\max}] = [-100.0, +100.0]$

## 5. Phase 2A Evidence Intelligence Summary `[IMPLEMENTED]`

Phase 2A adds statistical observation volume confidence, latest-vote model consensus, validation freshness, and dual ranking as query-time intelligence (detailed in [`docs/08.3-FEATURE_RECOMMENDATION_PHASE_2A_EVIDENCE_INTELLIGENCE.md`](file:///c:/Users/admin/PycharmProjects/AruMLStudio/docs/08.3-FEATURE_RECOMMENDATION_PHASE_2A_EVIDENCE_INTELLIGENCE.md)):

1. **Evidence Confidence ($C$)**:
   $$C = \sqrt{C_{\text{runs}} \times C_{\text{models}}} = \sqrt{\left(1 - e^{-N_{\text{runs}}/3.0}\right) \times \left(1 - e^{-M_{\text{unique}}/2.0}\right)}$$
   - $N=1, M=1 \implies C = 33.4\%$ | $N=2, M=2 \implies C = 55.5\%$ | $N=3, M=3 \implies C = 70.1\%$
2. **Model Consensus & Strict Tie Contract**: Reconstructs latest vote per model. 50/50 split &rarr; `SPLIT (50%)` with `is_consensus_tie = True`.
3. **Freshness Bands**: $\le 7\text{d} \implies \text{Fresh}$, $8\text{–}30\text{d} \implies \text{Recent}$, $> 30\text{d} \implies \text{Stale}$.
4. **Dual Ranking System**:
   - **`priority_rank` (Phase 1 Authoritative)**: Order by `evidence_score DESC, keep_runs DESC, feature_name ASC`.
   - **`operational_priority_score`**: $\text{round}(\text{evidence\_score} \times C, 2)$
   - **`advisory_rank` (Phase 2A Preview)**: Order by `operational_priority_score DESC, keep_runs DESC, feature_name ASC`.

## 6. Phase 2B Stability, Risk Badges & Generalization Summary `[IMPLEMENTED]`

Phase 2B implements query-time behavioral stability, score range spread, direction reversals, Level-1 cross-context generalization, and explicit multi-dimensional risk badges (detailed in [`docs/08.4-FEATURE_RECOMMENDATION_PHASE_2B_STABILITY_RISK_GENERALIZATION.md`](file:///c:/Users/admin/PycharmProjects/AruMLStudio/docs/08.4-FEATURE_RECOMMENDATION_PHASE_2B_STABILITY_RISK_GENERALIZATION.md)):

1. **Score Volatility & Trajectory Variance ($N \ge 3$)**:
   $$\sigma_S = \sqrt{\frac{1}{N - 1} \sum_{t=1}^N (S_t - \bar{S})^2} \quad (\sigma_S < 15.0 \implies \text{Stable},\ 15.0 \le \sigma_S < 35.0 \implies \text{Moderate},\ \sigma_S \ge 35.0 \implies \text{Volatile})$$
   - $N < 3 \implies \text{None}$ and displays `⚪ N/A (< 3 runs)`.
   - Score Range Spread $\Delta S = \max(S_t) - \min(S_t)$, Trajectory Direction Flips $D_{\text{flips}}$.
2. **Level-1 Cross-Context Generalization ($K \ge 2$)**:
   $$G = A_{\text{context}} \times \left(1.0 - \min\left(1.0, \frac{\Delta S_{\text{context}}}{100.0}\right)\right)$$
   - Evaluated across matching market, window, and project dimensions differing only by sampling interval.
   - $G \ge 0.75 \implies \text{Universal}$, $0.50 \le G < 0.75 \implies \text{Scale-Robust}$, $0.25 \le G < 0.50 \implies \text{Scale-Sensitive}$, $G < 0.25 \implies \text{Scale-Specific}$. Single context displays `⚪ Single Context`.
3. **Explicit Multi-Dimensional Risk Badges**:
   - `[DEGRADED]` (Score $\le -40.0$), `[SPLIT]` (`is_consensus_tie`), `[STALE]` ($> 30\text{d}$), `[UNSTABLE]` ($\sigma_S \ge 35.0$).
   - Composite scalar risk score was explicitly rejected to maintain transparency.
